### 1

**Problem.** `matchRmDangerous` ignores the shared parser. It splits segments with `command.split(/&&|\|\||[;|&\n]/)` (`:64`), words with whitespace plus an edge-quote trim (`:20-26`), skips its own 5-entry `WRAPPERS` (`:7`), and compares `program === 'rm'` with no basename (`:46`). `bash-text-rules.ts:19` already has 15 wrappers and `simpleCommands` (`:165-172`) already handles grouping, substitutions and quotes; only dotenv-guard uses it (`dotenv-guard-rules.ts:56-58`).

**Why it hurts.** README:12 promises "Each part of a compound line is checked". These pass today: `time rm -rf /`, `if true; then rm -rf ~; fi`, `{ rm -rf ~; }`, `(rm -rf ~)`, `echo $(rm -rf ~)`, `! rm -rf /`, `/bin/rm -rf ~`, `\rm -rf ~`, `rm -rf "$HOME"/` (target read as `$HOME"/`). Models write `if`/subshell/brace shapes routinely. Every parser fix since 10-11 (four dotenv-driven commits) skipped this guard.

**Evidence.**
```ts
const all = segment.trim().split(/\s+/).filter(Boolean).map(word => word.replace(/^["']|["']$/g, ''))
```

**Strategy.** Rebuild `matchSegment` on `simpleCommands(text)` with `basename(program)`; keep the current split only when `simpleCommands` returns `undefined`, as `blockedEnvIn` does. Same signature, so `register.ts:425` is untouched. Add test rows for each shape above first (red), then switch.

### 2

**Problem.** `matchDangerous` runs `new RegExp(pattern).test(command)` (`:26-28`) over text that still carries raw quotes. Flags are literal strings (`reset --hard`, `clean -f`, `branch -D`, `:13-17`); `GIT_OPT` (`:4-6`) knows seven global options; `WHOLE_TREE` (`:8`) allows only flags before `.`.

**Why it hurts.** README:9 says these are blocked "even with global options before the subcommand". These pass: `git clean -xdf`, `git clean -d -f`, `git clean --force`, `git reset HEAD~1 --hard`, `git reset -q --hard`, `git checkout HEAD -- .`, `git restore -s HEAD .`, `git branch --delete --force x`, `git -P push`, `git --bare push`, `git --work-tree /x push`, `"git" push`, `git p""ush`. Each new spelling would be one more regex row.

**Evidence.**
```ts
`${GIT_PREFIX}reset --hard`,
`${GIT_PREFIX}clean -fd`,
`${GIT_PREFIX}clean -f`,
```

**Strategy.** Decide on `simpleCommands` words: program basename `git`, skip global options (value-taking ones consume the next word, as `commitArgs` does at `bash-text-rules.ts:68-75`), then match subcommand + normalised flag set (`f` letter or `--force` for `clean`, `--hard` anywhere for `reset`, a lone `.` pathspec anywhere for `checkout`/`restore`). Keep the regex list as the unparsable fallback. Existing `git-guard.test.ts` rows must stay green.

### 3

**Problem.** `matchSecretCommand` tokenizes with `command.split(/[\s;&|<>=()"'`,]+/)` (`:72`) and matches each fragment alone, even when the command parses.

**Why it hurts.** A quote mid-path cuts the path in two: `cat "$HOME"/.aws/credentials` (token becomes `/.aws/credentials`), `cat ~/.a''ws/credentials`, `cat ~/".aws"/credentials` all pass. `"$HOME"/…` is a quoting style agents produce constantly. Key-name rules (`id_rsa`) mostly survive because the basename survives the split. The same split also blocks mentions (`echo "id_rsa"`, `grep -rn "id_ed25519" docs`), which decision 2 says should pass.

**Evidence.**
```ts
for (const token of command.split(/[\s;&|<>=()"'`,]+/)) {
```

**Strategy.** Match on `simpleCommands` path words (quotes already removed), plus `VAR=`/`--flag=` values, the way dotenv's `pathsOf` does; keep the punctuation split as the unparsable fallback. Return shape `{ path, rule }[]` stays, so the existence check in `register.ts:416-418` is unchanged.

### 4

**Problem.** `fail-closed.test.ts:45-46` says "the first one registered answers: git-guard for Bash, dotenv-guard for the file tools". The fail-closed tests in `rm-guard.test.ts:59-64` and `secret-guard.test.ts:84-90` assert only `toContain('failed')`, which the earlier guard satisfies. Row tests use `expectDeny` on messages that git and rm produce byte-for-byte identically (`git-guard-rules.ts:30-32`, `rm-guard-rules.ts:71-73`); `bash-inert-text.test.ts:73` accepts `reason === GIT || reason === RM`.

**Why it hurts.** Decision 5: a throwing `tool.call` handler without `.catch` lets the call through. Deleting `.catch(failClosed)` from the dotenv-Bash, secret-Bash or rm-guard handlers (`register.ts:403, 421, 427`) leaves every test green, so a guard can fail open with green CI. An rm-guard row can pass because git-guard denied it.

**Evidence.**
```ts
// With no store mocked, every toggle read fails before `next`. When several guards watch the same
// tool, the first one registered answers: git-guard for Bash, dotenv-guard for the file tools.
```

**Strategy.** Per guard: mock the store so earlier guards are off (`/c-mods <guard> off`, as `rm-guard.test.ts:289-291` does), force a throw only the target reaches (a non-string command makes `executedText` throw), and assert the exact text `c-mods: <guard> failed, command blocked.` In row tests, assert the pattern name in the message. Tests only; no production change.

### 5

**Problem.** `PIPE_TO_SHELL = /\b(curl|wget)\b[^|;&\n]*\|\s*(sudo\s+)?(sh|bash|zsh)\b/` (`:1`) knows three shells, allows only bare `sudo` before them, and requires the shell right after the first pipe. `bash-text-rules.ts:14` keeps a separate 12-entry `SHELLS` list.

**Why it hurts.** These pass: `curl x | /bin/bash`, `curl x | sudo -E bash`, `curl x | tee f | sh`, `curl x | dash`, `bash <(curl -s x)`. README:12 lists only sh/bash/zsh, so `dash` is within the letter of the docs, but `/bin/bash` and `sudo -E bash` are not.

**Strategy.** Check the parsed pipeline: a `curl`/`wget` command followed later in the same pipeline by any program whose basename is in the shared `SHELLS` list (exported from `bash-text-rules.ts`), plus a process-substitution `bash <(curl …)` row. Keep the regex as the fallback. Lands naturally with row 1.

### 6

**Problem.** The bare `'push --force'` and `'reset --hard'` (`:21-22`) match anywhere in the executed text. `${GIT_PREFIX}clean -fd` (`:15`) is fully covered by `clean -f` (`:16`).

**Why it hurts.** Decision 1: these are leftovers from the old shell hooks, not a deliberate catch-all. Decision 2: mentions should pass, as dotenv's do (README:10, :18). Today `grep -n "reset --hard" README.md`, `echo "never reset --hard"` and `gh pr create --body "then git push"` are denied. Live: this very review's `git log -S"'reset --hard',"` was blocked by the installed plugin. Removing a row is also unsafe to reason about while some rows are redundant.

**Strategy.** Delete the two bare rows and the redundant `clean -fd` after row 2 lands, so anchored matching already covers every spelling the bare rows caught; run the existing rows after each deletion. Add rows asserting the mention cases pass.

### 7

**Problem.** `HOME_ANCHORED` (`:24`) restates the anchored rules written inline at `:56-65`; `matchHomeFree` (`:27-33`) repeats the key/extension/tool-file checks at `:57, 61-63`. After `:50` returns for `home === ''`, `root` (`:53`) can never be `undefined`, so every `root !== undefined` (`:54, 58, 64, 65`) is dead.

**Why it hurts.** Adding `~/.kube/config` means a new branch *and* a new `HOME_ANCHORED` entry. Add only the branch and an absolute `/home/u/.kube/config` checked with HOME unset is no longer denied: the exact gap 3e59ca6 closed, with no test linking the two lists. The dead checks suggest a third state that doesn't exist.

**Strategy.** One table of home-anchored rules (`{ anchor, kind: 'dir' | 'file', label, except? }`) read by both `matchSecretPath` and `matchWithoutHome`; `matchSecretPath` calls `matchHomeFree` for name-only rules in the current order (key names before home dirs before extensions, so `~/.ssh/x.pem` still reports `~/.ssh`). Drop the dead `root` checks. Existing labels stay byte-identical.

### 8

**Problem.** `programIndex` (`:33-34`) skips assignments and wrapper words but not the wrapper's own options, so `simpleCommands('sudo -u root rm -rf /')` reports program `-u`, and `env -i rm` reports `-i`. `nice` is in no wrapper list.

**Why it hurts.** Rows 1-3 move guards onto `simpleCommands`; without this, `sudo -u root rm -rf /` stays a bypass after that work, and dotenv-guard already misses `sudo -u x cat .env` today. Local: dotenv and inert-span detection read the same index.

**Strategy.** Give each wrapper the options it takes a value for (`sudo -u/-g/-C`, `env -u`, `nice -n`), skip flags after a wrapper, add `nice`. One function, rows for each in `bash-text-rules.test.ts`.

### 9

**Problem.** The punctuation split `/[\s;&|<>=()"'`,]+/` is written in `dotenv-guard-rules.ts:52` and `secret-guard-rules.ts:72`. The `.`/`..` fold loop is written in `rm-guard-rules.ts:10-18` (`fold`) and `secret-guard-rules.ts:9-18` (`normalize`). The deny template is identical in `git-guard-rules.ts:30-32` and `rm-guard-rules.ts:71-73`.

**Why it hurts.** A tokenizer or fold fix lands in one copy; the wrapper and shell lists (rows 1, 5) already show this drift happening. The shared template is also why row 4's tests can't tell git from rm.

**Strategy.** Export one `fallbackTokens` from `bash-text-rules.ts`, one `foldPath` beside `basename` in `bash-parser.ts`, and give each guard its own name in its message (`BLOCKED (rm-guard): …`), updating the substring assertions.

### 10

**Problem.** `bash-parser.ts:4-5` documents "One exception: a `$(cat <<'EOF' ... EOF)` substitution is read as inert text"; `QUOTED_CAT_HEREDOC` (`:42-43`) and `:197-200` return `runsCode: false`. CLAUDE.md says the parser "holds no guard policy"; the rest of the inert policy is in `bash-text-rules.ts` (`HEREDOC_READERS`, `inertSpans`).

**Why it hurts.** Changing what counts as inert means editing two modules, and the exception reaches every parser consumer through the `runsCode` recursion. Decision 6: it was put there because it was easier.

**Strategy.** Have the parser report a heredoc-in-substitution node and let `bash-text-rules` decide it is inert. Low priority; do it when a change touches inert spans.
